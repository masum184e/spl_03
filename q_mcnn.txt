### 2. `target_size` vs checkpoint metadata

The dataset default is:

```python
target_size=(768,768)
```

while the checkpoint metadata says:

```python
"input_size": (512,512)
```

Those two values do not match in the shown code.

So for your thesis documentation, you should be careful not to claim 512×512 input if this exact training configuration used 768×768.

The source code itself explicitly stores `(512, 512)` in the checkpoint metadata. 

---

### 3. `gt_downsample=4`

The actual density-map output from the architecture is:

```text
768 / 4 = 192
```

so the model's natural output resolution corresponds to:

```text
192 × 192
```

for a 768×768 input.

---

### 4. `shuffle=True` and train/validation splitting

The dataset itself is shuffled and then the indices are separately shuffled before splitting.

The second shuffle is what explicitly randomizes the train/validation split.

---

### 5. Test set isn't used during training

That's good.

The code creates:

```python
test_set
test_loader
```

but the shown training loop only uses:

```text
train_loader
val_loader
```

So the test set remains untouched during model training.

# 105. The architecture in thesis language

If you need to explain this during your thesis defense, you can say:

> The density-estimation branch uses a custom four-column Multi-Column Convolutional Neural Network. The network processes the input image through four parallel convolutional columns with progressively different receptive-field sizes. The first column uses \(11\times11\), \(9\times9\), and \(7\times7\) kernels, while the subsequent columns use \(9/7/5\), \(7/5/3\), and \(5/3/3\) kernel configurations. Each column contains two \(2\times2\) max-pooling layers, resulting in a spatial downsampling factor of four. The extracted features from the four columns are concatenated along the channel dimension, producing 304 feature channels, which are subsequently fused using \(1\times1\) convolutions to generate a single-channel density map. A ReLU activation is used at the output to maintain non-negative density values. 

And for the loss:

> The model is trained using a combined objective consisting of a pixel-wise mean squared error between the predicted and ground-truth density maps and an absolute counting error obtained by summing the predicted density map. The density-map loss receives a weight of 0.9, while the counting loss receives a weight of 0.1.

# 107. The single most important idea

If you remember only one thing from this entire code, remember this:

> **The network does not directly predict the number of people. It predicts a spatial density map, and the total crowd count is obtained by summing the density map.**

So:

$$
\boxed{
\text{Image}
\rightarrow
\text{Density Map}
\rightarrow
\text{Sum}
\rightarrow
\text{Crowd Count}
}
$$

And your training simultaneously teaches the network:

$$
\boxed{
\text{“Predict the correct density everywhere”}
+
\text{“Predict the correct total number”}
}
$$

with:

$$
\boxed{
L=0.9L_{\text{density}}+0.1L_{\text{count}}
}
$$

That is the core of the entire implementation.
